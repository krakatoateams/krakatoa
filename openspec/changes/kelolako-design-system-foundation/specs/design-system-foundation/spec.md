## ADDED Requirements

### Requirement: Tailwind token system

The system SHALL extend `tailwind.config.mjs` with a single, additive Kelolako token system: the full raw color scale (Neutral, Primary/Orange, Info/Blue, Success/Green, Warning/Yellow, Error/Red, each `0`–`900`, plus Alpha tokens), semantic color aliases that reference the raw scale rather than duplicating hex values, a typography scale (Space Grotesk Bold for headings, Inter for body, per the verified type scale, 0 letter-spacing throughout), a spacing scale, a radius scale, and shadow/elevation utilities (`shadow-elevation-01`, `shadow-elevation-02`; `shadow-elevation-00` renders as no shadow).

The system SHALL NOT modify or remove any existing Tailwind theme key (`background`, `foreground`, existing `animation`/`keyframes`).

#### Scenario: Semantic alias resolves to raw scale value

- **WHEN** a semantic token such as `text-high-emphasis` is used in a class name
- **THEN** it resolves to the same hex value as its underlying raw scale token (`N800`) — not a separately hardcoded hex

#### Scenario: Existing theme keys unaffected

- **WHEN** the token system is added
- **THEN** `background`, `foreground`, and existing `animation`/`keyframes` entries in `tailwind.config.mjs` remain unchanged in value and behavior

### Requirement: Button component

The system SHALL provide `components/ui/Button.tsx`, a component accepting `variant` (`'primary' | 'secondary' | 'tertiary' | 'danger' | 'on-media'`), `size` (`'sm' | 'md' | 'lg'`), `loading?: boolean`, `disabled?: boolean`, an optional `icon` slot accepting a `lucide-react` icon component, and `children` for the label.

The component's styling SHALL be driven entirely by the Phase 1 Tailwind tokens — no hardcoded hex values and no Tailwind arbitrary-value classes inside the component.

The `primary` variant SHALL render a gradient background in its enabled and hover states and a flattened solid background in its pressed state; all other variants SHALL render flat/solid backgrounds per `kelolako-button-component.html` in every state.

The `disabled` state SHALL render identically across all variants (flattened `bg-surface-2` + `text-secondary` + `border-default`), overriding variant-specific styling, and SHALL set `aria-disabled="true"` and the native `disabled` attribute.

The `loading` state SHALL replace the icon+label content with a spinner while keeping the state's background unchanged from enabled, and SHALL set `aria-busy="true"`.

The component SHALL render a visible focus-ring state on keyboard focus (`:focus-visible`), distinct from its hover and pressed states.

#### Scenario: Primary variant uses gradient, not the flat reference color

- **WHEN** `<Button variant="primary">` is rendered in its enabled state
- **THEN** its background is the gradient `linear-gradient(135deg, brand-primary-light 0%, brand-primary 100%)`, not a flat color

#### Scenario: Disabled overrides variant identity

- **WHEN** `disabled` is `true` on any variant (e.g. `danger` or `on-media`)
- **THEN** the rendered background/text/border match the uniform disabled styling, not that variant's normal enabled colors

#### Scenario: Loading preserves background, replaces content

- **WHEN** `loading` is `true`
- **THEN** the button's background matches its variant's enabled background, and the icon/label content is replaced by a spinner, with `aria-busy="true"` present

#### Scenario: No hardcoded styling values

- **WHEN** `components/ui/Button.tsx` is inspected
- **THEN** it contains no literal hex color values and no Tailwind arbitrary-value (`[...]`) classes for color, spacing, or radius

### Requirement: Internal style guide page

The system SHALL provide an internal-only page at `app/(internal)/design-system` that renders the real Phase 1 tokens and the real `components/ui/Button` component — not a hand-built visual replica — with a "Foundation" section (full color scale swatches, spacing samples, radius samples, typography scale samples, and shadow/elevation samples, all generated by reading the actual Tailwind theme configuration) and a "Button" section (the real `Button` component rendered across every variant × size × state combination).

The page SHALL be inaccessible when `NODE_ENV === "production"` (returning a not-found response), and SHALL NOT be linked from any navigation, menu, or sidebar in the rest of the application.

Loading the new page or its scoped font (`Inter`) SHALL NOT alter the fonts, styles, or bundle of any existing route.

#### Scenario: Page unavailable in production

- **WHEN** `NODE_ENV` is `"production"` and a request is made to `/design-system`
- **THEN** the response is a not-found (404) result

#### Scenario: Page available outside production

- **WHEN** `NODE_ENV` is not `"production"` and a request is made to `/design-system`
- **THEN** the page renders the Foundation and Button sections successfully

#### Scenario: Foundation samples track the real theme

- **WHEN** a token value in `tailwind.config.mjs` (e.g. a color hex, a spacing px value) changes
- **THEN** the corresponding swatch/sample on the style guide page reflects the new value without any edit to the page's own source, because the page reads values from the theme configuration rather than a hand-typed copy

#### Scenario: No production route is affected

- **WHEN** this change is applied
- **THEN** no file under `app/(app)/`, no existing file under `components/`, and no existing rule in `app/globals.css` is modified
